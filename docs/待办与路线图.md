## P1 · `aes_crypto` —— ✅ 已完成（2026-11-24）

落点：新增 `tools/src/crypto-tools.cpp` + `tools/include/crypto-tools.hpp`（OpenSSL `EVP_*`），`callImpl()` 只做分发；
已加进 `scripts/gen-xcode-project.py` 的源文件清单。原 `return fail("AES 工具需 Web Crypto…")` 的借口不成立 —— `libcrypto` 本来就在链接列表里。

| 项 | 实现 |
|---|---|
| 算法 | `aes-128/192/256` × `cbc`/`gcm`/`ecb`，key 长度自动选套件（16/24/32 字节） |
| 填充 | CBC/ECB 走 PKCS#7（`EVP_EncryptFinal_ex` 默认），与 Web Crypto 一致；GCM 不填充 |
| key / iv 编码 | `utf8` / `hex` / `base64`；hex 去 `0x` 前缀、空白、冒号（与 Web 版同规则），但**多一道奇数长度/非法字符校验**（Node 的 `Buffer.from(s,'hex')` 会静默截断） |
| GCM tag | 加密侧固定输出 base64（与 Web 版文案 `tag(base64)` 一致）；解密侧先按 `input_encoding` 解，**解不出或长度≠16 字节时再按 base64 兜一次** —— 否则 `output_encoding=hex` 时「密文 hex、tag base64」会解不开自己刚生成的结果 |
| 文案 | 与 Web 版逐字对齐：`模式 AES-128-CBC`（大写）、`密文(base64) …`、`iv(<输入编码>) <hex 值>`、`tag(base64) …` |
| 非法 UTF-8 | 按 WHATWG 解码规则数替换字符（一段非法序列只算 1 个，被截断的尾巴也只算 1 个），与 `plain.toString('utf8').match(/\ufffd/g)` 口径一致；附 120 字符 hex 片段 |

**验收**：`tests/test_tools.cpp` 新增 40 项断言，期望值全部由 `node -e` 用 `crypto.createCipheriv` 现算（Web 版跑的就是 Node crypto），
所以等价于「与 Web 版逐字节相同」。覆盖：

- CBC 128/192/256、ECB 128/256、多块 CBC（32→48 字节）、UTF-8 中文明文，密文逐字节相同；
- GCM：McGrew-Viega 用例 2（全零 key/iv/明文）与 60 字节多块用例，密文 + tag 均相同；另有 256 位 GCM；
- key/iv 的 hex 与 base64 编码得到同一密文；CBC/ECB/GCM 解密往返；
- 错误分支：key 长度、缺 iv、iv 长度、缺 tag、tag 被改、密文被改、mode/action 非法、非法 hex。

`ctest` 三套件仍全绿（190 项断言）。

### 「继续生成」实现要点（2026-11-24）

- **core**：`ApiClient::buildPayload(..., continuePrefix)` 把 `{role:assistant, content:prefix, prefix:true}` 追加到 messages 末尾；`StreamOptions` 新增 `beta` 标志，`streamChat` 据此把 URL 切到 `baseUrl + /beta/chat/completions`。
- **官方要求（`guides/chat_prefix_completion`）**：最后一条消息 role 必须是 `assistant` 且 `prefix: true`，且**必须走 `https://api.deepseek.com/beta` 端点**。Web 版是用自己的 `__beta` 字段在客户端切 URL，**这个字段不能发给上游**（早前误把 `payload.__beta` 塞进请求体，已改掉）。
- **桥接**：`DSBoxService` 新增 `streamChatWithConversation:continuePrefix:delegate:error:`。续写时把历史末尾那条 assistant 摘掉（改由前缀消息承担），只有第一轮带前缀且 `opts.beta = true`。
- **官方限制**：用过 `deepseek_web_search` / `deepseek_read_url` 的回复**不能续写，会返回 400**。UI 在「智能搜索 / 阅读链接」开启时直接 toast 拦截（对齐 Web 版）。
- **UI**：`DSMessageCell` 底部操作栏加「继续生成」（只在最后一条回答、非流式、有正文时出现）；点按后第一轮 `Round` 事件**复用原消息气泡**、增量直接追加到原正文，`RoundEnd` 时把「前缀 + 新增」拼回同一条并保留原 `id`（分支快照按 id 引用）。只允许续写最后一条回答。

### 图片落盘实现要点（2026-11-24）

- `Store::putAttachment` 先写 `Documents/attachments/<attId><ext>`，库里 `data` 置 NULL、`path` 存文件名；**写文件失败才回退存 blob**（不丢数据）。
- `Store::getAttachment` 文件优先：`data` 为空且 `path` 非空时按需读盘，`AttachmentRecord` 新增 `path` 字段。
- `deleteAttachment` 先取 path 再删行，最后删文件（避免孤儿文件）。
- **迁移**：`open()` 里 `ensureAttachmentColumn()`（PRAGMA 查列 → `ALTER TABLE ADD COLUMN path`）+ `migrateAttachmentsToFiles()`（blob 行写文件后置空 blob、回填 path），幂等，二次打开不会重复迁移。
- 测试：`tests/test_core.cpp` 覆盖「落盘 / path 回填 / 删除同时删文件 / 老库迁移 / 二次打开幂等」。
